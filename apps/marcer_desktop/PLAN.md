## 2. Phase 1 — `marcer_catalog` (data layer)

Reimplementation of the spec contract in Dart (the project's established
"spec as contract, reimplementation as a feature" pattern):

- **Overlay merge** exactly per `SPEC.md` §7 (R11–R17):
  - recursive at every level, union of dir names and ZIP names compared
    case-insensitively, each name once;
  - directories first, then `.zip` files (case-insensitive suffix), both groups
    sorted case-insensitively ascending;
  - hidden entries and `@eaDir`-style junk ignored;
  - effective path = patch path when `InPatch` else root path (patch wins);
  - absolute paths / `..` sanitized; never escape `RootDirectory` / `PatchDirectory`;
  - `Parent` at root = silent no-op; FS errors = empty list + error surface, no crash.
- **Gameinfo join** per `ANALYSIS-game-data.md` §4.2: split `index.json` rel path into
  parts → `letter = parts[2]`, `folder = parts[3]` (0-based), join to
  `games-cracked.json` (+ optionally `games-pd.json`, `games-utils.json`).
- **Screenshot index lookup**:
  - load `<OutDirectory>/index.json` (`version` + `entries` map keyed by rel zip path);
  - **gotcha:** on disk `preview` and `candidates[]` are *basenames* — the real PNG is
    `OutDirectory + "/" + dirname(rel) + "/" + preview` (same rule as
    `tools/gallery/gallery.py::_full_png`);
  - status aggregation / primary preview selection mirrored from the gallery spec
    (`done → desktop → no_usable_shots → interrupted → pending → skipped_disk_n`).
- **Graceful degradation** (DECISION §7): missing `index.json`, missing `Data/` dir or
  missing trees → empty states with a notice, never a crash.
- **Read-only guarantee**: the package never writes to `RootDirectory`,
  `PatchDirectory`, `<OutDirectory>` or `<DataDirectory>`.
- **Unit tests**: small fixture trees covering overlay rules (BOTH/ROOT/PTCH flags,
  patch precedence, case-insensitive dedup, traversal attempts), join resolution,
  preview path resolution, and degradation when artifacts are absent.

## 3. Phase 2 — `desktop.config.json`

Own schema (decided), committed only as `desktop.config.example.json`; the real file is
git-ignored (same policy as `launcher.config.json`).

```json
{
  "RootDirectory": "",
  "PatchDirectory": "",
  "OutDirectory": "",
  "DataDirectory": "",
  "Hatari": {
    "Executable": "",
    "ConfigFile": "",
    "ArgsTemplate": "-c \"{cfg}\" --disk-a \"{zip}\""
  },
  "Window": { "width": 1280, "height": 800 }
}
```

- Field names follow the `SPEC.md` §5 style.
- **Absolute paths** in the config (decided 2026-10-11); relative paths, if used
  anywhere, resolve against the application directory (R10, same rule as the console app).
- `Hatari` is part of the schema but **unused in the MVP** (launch = Phase 5+).
- `OutDirectory` (screenshot archive) and `DataDirectory` (gameinfo JSONs) are desktop-only
  fields; `DataDirectory` default convention is `<PatchDirectory>/../Data`
  (per `ANALYSIS-game-data.md` §5.5) when left empty.
- `run.sh` still sources `local/paths.env` for developer convenience, but only to
  **seed/print** a working `desktop.config.json` on first run — the app itself reads
  only the config file.
- **Config resolution (2026-10-11):** `desktop.config.json` is searched in order —
  (1) current working directory, (2) the executable's directory (portable ZIP
  release), (3) macOS: the folder containing the `.app` bundle. Release ZIPs ship
  `desktop.config.example.json`.

## 4. Phase 3 — Desktop UI (Surface A, read-only) — **implemented 2026-10-11**

Playnite-inspired master-detail layout, hybrid model:

- **Top bar (gallery-style, 2026-10-11):** section tabs `cracked` / `pd` /
  `utils`; search field (`/` focuses, Esc clears) with 250ms debounce;
  status / publisher / crew / cracker / language / year dropdowns (facet
  dropdowns type-to-filter/jump); tri-state `raw` / `pasti` / `boxscan`
  (`any`/`yes`/`no`); `TOS/Bad`; sort (`name`/`year`/`publisher`/`cracker`/
  `crew`) + asc/desc; `clear`; letter row (`any`, `0-9`, `A`–`Z`, dimmed when
  absent from facets). Field order matches the gallery webapp. Facet values
  come from `CatalogUniverse` (index.json + gameinfo, **no FS scan**).
  Section switches reset the incompatible filters (status → `DefaultStatus`,
  raw/pasti/boxscan/tos/crew/cracker → `any`, cracker sort → name on pd)
  exactly like the gallery tabs.
- **Default view (2026-10-11):** the app starts in the **catalog grid**
  (`AppView.catalog`, `catalogMode`); the overlay folder browser is an
  optional mode toggled with `T` (or the Folders/Catalog button). The filter
  bar (tabs, search, facets, sort, letters) is shown in catalog mode only —
  switching to the folder browser hides it but keeps the filter state.
- **Catalog mode:** the global card grid (`CatalogFilter.isActive` only
  decides whether the result is considered "filtered"); `clear` resets the
  filters. Result counts in the status bar. **Status bar** mirrors the gallery
  (`renderStats`/`renderFooter`): `N / M with screenshot`, status counts
  (`done`/`desktop`/`pending`/…), `info N folders`, `index.json: <mtime>`,
  `gameinfo: <generated_at>`, plus degradation notices.
  **Crew/cracker focus** (gallery `_apply_focus`): with an active crew or
  cracker filter (cracker takes precedence) each card's preview/status
  reflects that group's ZIP variant — even when it has no screenshot — and
  the lightbox opens on exactly that variant (`focusVariant`). Matching is
  fuzzy: normalized (`&`/`+` = "and") substring, then (crew only) a gameinfo
  cracker fallback, then a token-subset match tolerating typos/missing
  connectives; the first match with a preview wins. When no ZIP can be
  identified the card shows a hint plus up to four other variant
  screenshots. Grid cards show an `×N` chip for multi-ZIP folders, a 2×2
  grid of up to four variant screenshots when no focus is active and ≥2
  variants have a screenshot, and (when `ShowCandidates` is true, single
  variant, no focus) a candidate thumb strip; clicking a thumb opens the
  lightbox on that image.
- **Left:** overlay folder tree per `SPEC.md` §7 with `Enter`/`Backspace` semantics,
  layer labels `BOTH`/`ROOT`/`PTCH`, virtual `Favorites` folder per `SPEC.md` §11
  (stored in `favorites.txt`, keyed by effective path).
- **Center:** list view (SPEC §9.1 line format, §10 keys, §9.3 colors) **or**
  grid/icon view — auto: grid in catalog mode or when the folder contains at
  least one ZIP. Grid shows folder tiles, ZIP cards with preview and catalog
  `GameCard`s.
- **Lightbox (gallery-style):** Enter on a ZIP/card opens the lightbox —
  header with layer/status badges, position + variant counter, main image
  **integer-upscaled** (pixel-art stays crisp), variant filmstrip (short
  labels, status underline, `+N` candidate badges, tooltip, auto-scroll),
  candidate strip (fixed height, wraps images), info panel with release
  variants table (open ZIP highlighted) + "This ZIP" table; `←/→` item,
  `↑/↓` variant (wrap), `PgUp/PgDn` image (wrap), Esc close.
- **Right:** detail panel — large preview screenshot, candidate gallery, metadata
  (title, publisher, crew, language, disks, release, flags, `matched_via`) for
  entries and catalog cards.
- **Keyboard:** `SPEC.md` §10 bindings plus `/` (search), `T` (catalog/folder
  view toggle); mouse input additionally allowed (R8). Full keyboard control
  is a hard requirement for this surface.
- **Colors/rendering:** dark Playnite-like theme, but layer/selection colors follow the
  `SPEC.md` §9.3 mapping as the configurable baseline.
- **No launching in the MVP.**
